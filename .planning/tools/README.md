# Orchestrator tools (kept in the repo so a restart or a new session loses nothing)

- heavy.sh: runs one browser-heavy command in one of three slots (copy to the scratchpad's exec-011/ folder, or run from here; it keeps its locks beside itself).
- preview/build.py: builds the preview into a folder (page lists synced from diy.html, every asset with an extension, the two help preview files, files.txt). Publish the folder's diy-portal.html with every path in files.txt and `capabilities: {sample: {}}`.
- preview/diy-portal.html: the page published to the owner's preview link (https://claude.ai/artifact/GPhQRgiF3Kkne2A5VHqDxP). It loads the build's files by relative path; rewrite its script and style lists from diy.html for each build and bump its reset key. preview/b13-files.txt is the last build's file list (every file must have an extension).
  - Help in the preview: the page loads help-data.js and help-preview.js (both in preview/, preview only, never in a product page) right before assets/js/help.js (keep these two lines when the script list is rewritten from diy.html), so Help answers through the frame's `sample` capability, shown as the real Help dialog shows a server's answer. Each preview build must copy both files beside diy-portal.html (build paths `help-data.js` and `help-preview.js`, next to the page, not under assets/) and the publish must declare `capabilities: {sample: {}}`; without the capability Help shows "Help is not available right now." and the contact. Before each build run `node .planning/tools/preview/make-help-data.mjs --verify`; when it says STALE (a help guide merge), run it without --verify to regenerate help-data.js. Check: `.planning/phases/07-help-chatbot/checks/help-preview.js`.
- help-chat/help-chat.html: the owner's help chat page (https://claude.ai/artifact/Sbf9kfcoaqJd3svbb7tezj), published with guide.json beside it and the `sample` capability. Regenerate guide.json after any help guide merge: `node .planning/tools/help-chat/make-guide.mjs <dir>`, then republish.
