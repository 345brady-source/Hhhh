The sentences for a file that is not a PDF, fixed here and built in plan 07 (D-11). This table is the single source: plans 07 and 09 cite it. The orchestrator's decision (white label): no product name on screen, and none in a check, a comment, an identifier or a generated file name; the file type is called a word-processing document and the instruction names no program.

| Case | How it is known | Sentence |
|------|-----------------|----------|
| N1: a word-processing document | the name ends in .docx, .doc, .docm, .dotx, .dot, .rtf or .odt; or the contents are one (the two byte tests under this table) | "This is a word-processing document (.docx), not a PDF. Open it in the program it was written in, save it as a PDF, and upload that PDF." The ending in brackets is the file's own ending when it is one of those listed, and .docx when the file is known by its contents alone |
| N2: a word-processing document named .pdf | the name ends in .pdf and the contents are a word-processing document | "This file is named .pdf, but inside it is a word-processing document, not a PDF. Open it in the program it was written in, save it as a PDF, and upload that PDF." |
| N3: any other file that is not a PDF | the first bytes are not the PDF header | "This file is not a PDF. Save the agreement as a PDF from the program it was written in, and upload that PDF." |
| Hint under the agreement dialog's file input | always | "One PDF, up to 25 MB. A word-processing document has to be saved as a PDF first." |

The two byte tests for "the contents are a word-processing document", given as bytes so that no product name is spelled out: (1) the file begins with the zip header 50 4B 03 04 and, within its first 64 KB, an entry name begins with the five bytes 77 6F 72 64 2F; (2) the file begins with the compound-file header D0 CF 11 E0 A1 B1 1A E1 and holds anywhere the 24 bytes 57 00 6F 00 72 00 64 00 44 00 6F 00 63 00 75 00 6D 00 65 00 6E 00 74 00. In the product code and in the check each pattern is held as a list of byte values with a comment in neutral words ("the folder of a word-processing package's main part", "the main stream of an older word-processing file").

Where: a notice inside the dialog (`es-note es-note-bad`, `role="alert"`), shown when the file is chosen or dropped and again on submit, staying until another file is chosen; the file input is emptied; nothing is stored. Both upload dialogs show the same three sentences.

The label rule the page `qualifiedLabels` proves (D-06; the orchestrator's decision, built in plans 03 to 06):
1. A field named from a printed caption or label carries the document's own words as its label, always; its kind stays in `kind`.
2. A field of a known kind the reader already labels today keeps the portal's standard word only when the printed label is that kind's plain word (the cases the existing checks pin); where the printed label says more (which address, which phone, whose name), the label is the document's words.
3. Filling in from onboarding goes by kind and applies only where the printed label is the kind's plain word for that person; a qualified label is never filled in.
