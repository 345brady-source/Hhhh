## Summary

Document B is a partnership agreement of 32 pages. It has **two** printed places a person completes, both on page 31, both signature lines of the sponsor's side. It has no place for an investor anywhere: no signature page for limited partners, no joinder, no blank, no tick box, no date line. Thirty-one pages are prose, a contents list, a cover and an exhibit table, and must get nothing. [VERIFIED: every page rendered and looked at; machine sweep of all 32 pages: 0 underscores, 0 box or symbol characters, 0 stroked paths, 0 form fields, 9 filled hairline rectangles of which 2 are the signature rules]

The reader places exactly those two fields today, for the firm, unmarked, and nothing else. What it gets wrong is what it then says and allows: the read summary and the toast tell the sponsor to add a signature field for the investor (on a document that prints no place for one, against D-03), the editor is titled and worded as a subscription agreement every investor signs, saving is refused, and there is no way for the firm to sign the document. D-08 and D-10 are not met.

A second finding comes from experiment, not from the document itself: document B's second block is read as the firm's only because the signatory's printed title under the first line happens to be one of the reader's words for the firm. The same page with another title is read as the investor's and marked for review. A 6-line change in one function fixes the class and leaves the 47-field example untouched (prototyped in a scratch copy, not in the repository).

## Differences by convention class (cause → fix)

### C1. A document only the firm signs is described as a subscription agreement that lacks an investor signature (D-08) — FAILS TODAY

- **Class:** an agreement whose only printed places are the firm's (firm signature lines found, no place of any kind for the investor).
- **Cause:** `readNote` has one sentence for every reading without an investor signature line. [VERIFIED: /home/user/Hhhh/assets/js/esign.js:2971] verbatim: `out.push(r.investorPages.length ? \`The investor’s signature line was found on ${on(r.investorPages)}.\` : 'No signature line for the investor was found: add a signature field for the investor where they sign before saving.');` The note then always ends with the paragraph about fields for "Investor" [VERIFIED: esign.js:1789], and the editor's heading reads "place the fields once; each investor fills them in and signs during onboarding" [VERIFIED: esign.js:1788].
- **Fix:** in `readNote`, tell three cases apart by what was read, never by the document:
  1. nothing placed at all (prose, a blank file): today's sentences, unchanged;
  2. places for the investor but no investor signature line: today's sentence, unchanged;
  3. **firm signature lines and no investor place of any kind** (`r.firmPages.length > 0`, `r.investorPages.length === 0`, and no field of the draft belongs to an investor signer): say that the document is signed only by the firm, how many signature lines and on which page, that no investor signs it, and that the agreement investors sign during onboarding is a separate upload. Keep the opening words "No signature line for the investor was found" in this sentence, because existing checks look for them (see Risks). In case 3 leave out the closing paragraph about fields for "Investor" and change the editor's heading line.
- **Never fitted to one document:** the rule keys on the reading's own counts (firm signature pages, investor signature pages, investor fields). It names no word of the document.

### C2. The firm cannot complete a document only it signs (D-10) — FAILS TODAY

- **Cause:** `agreementTodo` refuses every draft without an investor signature field. [VERIFIED: /home/user/Hhhh/assets/js/esign.js:2982-2986] verbatim: `if (!inv || !signing(inv).length) {` … `if (env.read && !env.read.investorPages.length) return 'No signature line for the investor was found in this agreement. Add a signature field for the investor where they sign.';` The same sentence is the toast on arrival [VERIFIED: esign.js:3130]. `templateReady` requires the role `'Investor'` [VERIFIED: esign.js:686-691] verbatim: `(tpl.roles || []).indexOf('Investor') < 0) return false;`. So the only action on screen, "Save subscription agreement", can never succeed, and the two fields can never be signed.
- **Fix (recommended; needs the owner's yes, see Open questions):** keep the refusal to store such a document as the offering's subscription agreement (that is truthful: investors cannot sign it), change its wording for case 3 so it does not ask for an investor field, and add one action for case 3: the firm signs it. The pieces exist: an envelope may have the countersigner as its only signer [VERIFIED: esign.js:1360] verbatim: `if (!n.investors.length && !n.cs) return fail('Add at least one signer.');`; `sendCheck` asks only that each signer has a signature field [VERIFIED: esign.js:479-485]; `saveAgreement` already drops signers without fields [VERIFIED: esign.js:3159]; the console has the firm's signing screen (esign.js:1799-1874, found by search, not read through). The action turns the draft into an ordinary envelope whose only signer is the firm (no `agreementFor`, investor and co-investor placeholders removed), sends it to the firm's turn, and the completed PDF carries both signatures. Whether a firm-only envelope completes cleanly through the existing signing screen was not walked in this research [ASSUMED]: the plan's first task for C2 should walk it before building on it.
- **Never fitted to one document:** the action appears for case 3 of C1, whatever the document.

### C3. The firm's second block is read as the firm's by accident (D-07, D-09, D-12) — PASSES TODAY ON DOCUMENT B, FAILS ON ITS NEIGHBOURS

- **Class:** a signature block of the sponsor's side under a heading the reader's word lists do not know, identified by an entity name printed in full directly over its "By" line, standing below another block of the firm.
- **Evidence (synthetic one-page PDFs with invented names, same layout as page 31, scored through the upload dialog):**

| Variant | Today | With the prototype |
|---|---|---|

| no printed name under the lines; second heading names a kind of limited partner | 2 firm, second **marked for review**: FAIL (D-09) | 2 firm, 0 marked: PASS |
| a partnership agreement that does print a limited partner's page (blank name line, "By" line, name and title lines) | 1 firm + 4 investor, 0 marked: PASS | PASS (unchanged) |

| the 47-field example | 47, 0 marked | 47, 0 marked |
| document B | 2 of 2, 0 marked | 2 of 2, 0 marked |

- **Cause:** in the role loop of the block reader, a printed company name between the line and a heading counts only when that heading is the investor's; when the farther heading is the firm's and an unknown heading lies between, the rule "another heading starts a new block after that side's signature line: probably the other side" fires first. [VERIFIED: /home/user/Hhhh/assets/js/placement.js:1140-1145] verbatim: `} else if (named && hd.who !== 'firm') {` … `role = 'firm';` … `} else if (blocked && sigBetween(hd.y, blocked.y, own)) {` … `role = hd.who === 'investor' ? 'firm' : 'investor';`. In document B the walk upward never reaches that rule, because the line printed under the first rule ends in a word that is on the reader's list of words for the firm (`FIRM_WORDS`, placement.js:137, read this session) and so becomes a heading for the firm. And a block given to the firm by its printed name is never "sure", so it is marked (`sure` is not set in that branch).
- **Fix (prototyped):** a company name that stands between a block's own heading and its line makes the block the firm's whichever side the farther heading names, and it is sure when the name is the block's own (nearer than any other heading, within 90 pt of the line, no other signature line between). A company name above the block's own heading still belongs to the block before, so the "other side" rule keeps working for an investor block that follows the firm's. The diff (17 lines) is at `/tmp/claude-0/-home-user-Hhhh/718a3a12-5721-5a9e-a5ca-f390e1aa2396/scratchpad/owner-set/B/prototype-placement.diff`.
- **Never fitted to one document:** the rule is the existing one ("an investor's own name is never printed in the agreement", placement.js:1062-1064), applied in one more position. It was not run against the seven public documents or the nine check files in this research: the plan must.
