**The contract with the server (identical in plan 07-02):**
`POST /v1/help`, JSON: `message` (1 to 500 characters), `session` (optional, the id the server returned), `page`, `step`, `role` (`admin`, `team` or `investor`). A sponsor's call carries `Authorization: Bearer <API_TOKEN>`; an investor's carries `X-Invite-Token: <invitation token>`. 200: `{ ok: true, kind: 'answer' or 'cannot' or 'out_of_scope', answer, session }`. Failures: 400 invalid, 413 too_large, 402 spend_cap, 429 limit, 503 unavailable (no key), 504 timeout, 502 incomplete, invalid or failed, each `{ ok: false, reason }`.
Log line per call in CARROWVALE_READ_LOG: `{ at, route: 'help', ms, audience, page, turn, bound, outcome, stopReason, model, usage, cost, guide }`, `usage` holding input_tokens, output_tokens, cache_creation_input_tokens, cache_read_input_tokens.
Server settings the runner sets for its child process: PORT, API_TOKEN, DATA_KEY (32 random bytes, base64; invitations need both), STORE_FILE (a temporary file), RATE_LIMIT_PER_MIN=0, CARROWVALE_HELP_PER_HOUR=0, CARROWVALE_SPEND_CAP_USD and CARROWVALE_HELP_DAILY_USD (both the cap), CARROWVALE_READ_LOG (the shared log), CARROWVALE_HELP_MODEL and CARROWVALE_HELP_EFFORT (passed through when given), CARROWVALE_API_KEY (inherited from the caller's environment in the paid modes; removed from the child's environment in `--rehearse`).
