**Planner's choices (the owner may override):**
1. The per-address hourly limit is a setting (`CARROWVALE_HELP_PER_HOUR`, default 30, 0 turns it off) so the orchestrator's measurement can run many questions from one address without a code change.
2. A session belongs to the credential that opened it. A session id presented with another credential starts a new session, so an investor can never continue a sponsor's conversation.
3. The answer is also replaced when it uses the word AUTOPILOT forbids on every screen; a prompt rule alone cannot guarantee "never".
4. The log line carries `bound`, the input bound the cap used, so the measurement can prove on real rows that the bound was never below the real token count.
5. The assistant's earlier answers are kept and sent back as plain text only. Thinking blocks are never stored or sent back, so dropping old exchanges from the window cannot trip the service's check on replayed thinking.

**The contract (identical in plans 07-03 and 07-04; do not change it without changing them):**

Request: `POST /v1/help`, JSON, at most 8 KB. Fields: `message` (string, 1 to 500 characters after trimming), `session` (optional string the server issued), `page` (optional; kept only if it is a key of PAGES whose audience fits the asker), `step` (optional; kept only if `page + '/' + step` is such a key), `role` (optional: `admin`, `team` or `investor`; `investor` lowers the audience to investor; nothing raises it). Every other field is ignored.

Responses, all JSON with `Cache-Control: no-store`:
| Status | Body | When |
|--------|------|------|
| 200 | `{ ok: true, kind: 'answer' or 'cannot' or 'out_of_scope', answer, session }` | an answer; "do not have that"; "portal questions only" (also when the service refuses) |
| 400 | `{ ok: false, reason: 'invalid' }` | not JSON, not an object, no message, empty message |
| 413 | `{ ok: false, reason: 'too_large' }` | body over 8 KB or message over 500 characters |
| 402 | `{ ok: false, reason: 'spend_cap' }` | the shared cap or the daily help cap would be passed |
| 429 | `{ ok: false, reason: 'limit' }` | the session's 20 questions or the address's hourly limit |
| 503 | `{ ok: false, reason: 'unavailable' }` | no key; answered before the body is read |
| 504 / 502 | `{ ok: false, reason: 'timeout' or 'incomplete' or 'invalid' or 'failed' }` | as the reading routes |
The guards every /v1/ route already has keep their own bodies (401, 403, 410, the general limiter's 429).

Settings: `CARROWVALE_HELP_MODEL` (`claude-haiku-5-5`, the default, or `claude-sonnet-5-5`; any other value is the default), `CARROWVALE_HELP_EFFORT` (`low`, the default, `medium` or `high`), `CARROWVALE_HELP_DAILY_USD` (default 2; set and not a number refuses every call), `CARROWVALE_HELP_PER_HOUR` (default 30; 0 is off).

Log line (one per call that reached the library, when `CARROWVALE_READ_LOG` is set), exactly these keys: `{ at, route: 'help', ms, audience, page, turn, bound, outcome, stopReason, model, usage, cost, guide }`; `outcome` is one of `answer`, `cannot`, `out_of_scope`, `declined`, `guarded`, `incomplete`, `invalid`, `timeout`, `failed`, `spend_cap`, `limit`; `page` is the checked key or ''; `guide` is VERSION. Never the question, the answer, a name or an address.
