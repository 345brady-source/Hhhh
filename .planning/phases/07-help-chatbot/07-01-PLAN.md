**The generated module (what plan 07-02 imports; fixed here):** `server/lib/help-guide.mjs` exports
- `VERSION`: string, the first 12 hex characters of the SHA-256 of RULES, a newline, GUIDE.sponsor, a newline, GUIDE.investor.
- `RULES`: string, the text of server/help/rules.md (trimmed).
- `MARKER`: string, the token of the one line `Internal reference: <token>.` in the rules.
- `GUIDE`: frozen `{ sponsor, investor }`, each a string wrapped as `<guide audience="sponsor">` ... `</guide>` (or `audience="investor"`). The sponsor guide holds every entry (sponsors answer their investors' questions); the investor guide holds only entries whose audience is `investor` or `both`.
- `PAGES`: frozen object, one key per entry (a route name such as `console-investors`, or `invite/<step>` and `onboarding/<step>` for flow steps), each `{ title, audience, where }` where `audience` is `sponsor`, `investor` or `both` and `where` is a ready phrase for a sentence, built by the generator from `kind` and `title` by this rule only: console gives `the console page "<title>"`; portal gives `the investor portal page "<title>"`; step gives `the account setup step "<title>"` for keys under `invite/` and `the bank account update step "<title>"` for keys under `onboarding/`; page gives `the page "<title>"`.
The output is deterministic: no date, no machine path, keys in source order.

**The source format (server/help/guide.md):** a section `## <key>` per entry. The lines directly under the heading, up to the first blank line, are fields `name: value`: `audience:` (sponsor, investor or both), `kind:` (console, portal, step or page), `title:` (the page's name as the note will say it), `menu:` (optional, where it sits in the menu), and one or more `anchor:` lines (a fixed text the screen shows, present verbatim in the file that registers the route). Then free text. One section `## skip` lists `key: reason` lines for routes and steps left out.
