<interfaces>
NS.bankFiles (assets/js/bankfiles.js; pure; never fetches; never uses the browser's XML parser; never evaluates file content):
  LIMITS = { bytes: 2000000, lines: 20000 }
  detect(text) → 'ofx' | 'bai2' | 'csv' | ''          from the content, never the file name: 'OFXHEADER:' or '<OFX' → ofx; a first record starting '01,' with records ending '/' → bai2; two or more rows split by comma, tab or semicolon → csv
  cents(text) → integer or null                          '$1,234.56', '1234.5', '-12.00', '(12.00)', '12.00-' and '-200.0000' read exactly, digit by digit, with no floating point; a non-zero digit after the cents, letters, or two signs give null
  csvGuess(rows) → map = { date, text, amount | (in and out), balance, check, header: true|false, order: 'mdy' | 'dmy' | 'ymd', outNegative: true|false }   column indexes guessed from the header row and the values; the sponsor confirms it on screen (plan 11-15)
  parse(text, { kind, map }) → { kind, last4, currency, from, to, openingCents, closingCents, lines: [ { id, date, cents, text, ref } ] }   money in positive; openingCents and closingCents null when the file does not carry them; throws one plain sentence on any refusal
  lineIds(lines) → the same lines with id set: 'f:' + the bank's transaction id when there is one (OFX FITID), otherwise 'h:' + the first 16 hex digits of NS.audit.sha256(date|cents|text|n), n counting identical date, cents and text lines from 0 in file order
CSV rows are split with the same rules as csvRows in assets/js/invitations.js lines 1699-1735 (commas or tabs, semicolons when the first line has neither; quotes; a byte-order mark dropped): copied into bankfiles.js, because invitations.js keeps it private and is edited by phase 8.
OFX: one tokenizer reads <TAG>value pairs and closing tags and tracks open containers, so the layout with closing tags and the one without read the same; only &amp; &lt; &gt; &quot; &apos; are decoded; DTPOSTED's first eight digits are the date; TRNAMT is signed; FITID, CHECKNUM, NAME and MEMO are kept (text = NAME and MEMO joined by ' '); ACCTID's last four digits; LEDGERBAL BALAMT is the closing balance.
BAI2: records end with '/'; 88 continues the record before it; 01 file header, 02 group header (as-of date), 03 account (number, currency, summary codes), 16 transaction (type code, unsigned amount in cents, funds type, value date when V, bank reference, customer reference, text), 49 / 98 / 99 trailers with control totals and record counts, each checked.
