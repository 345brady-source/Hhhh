**Contract (plans 08-06, 08-07, 08-09, 08-13 and 08-15 build on it; do not rename):**
- The console sends invitation.package === true and invitation.clientId (1 to 80 letters, digits, underscores or hyphens, the billing key pattern) inside POST /v1/invitations.
- POST /v1/invitations then answers as today, or { error, code } with: 402 no_card | card_declined | authentication_required; 403 account_required; 409 billing_unavailable | package_unavailable | tier_mismatch | already_sent | package_used (package_used is consume's own code, met only when two posts race, N2); 400 for a package without a valid clientId. On each of these no invitation, blob or outbox message is stored.
- rec.package = { entitlement, tier, account, key } (account id, client id). package and clientId are never written into the snapshot's invitation object.
- Rows of GET /v1/invitations and GET /v1/invitations/:id carry package: null or { tier, status } with status "paid" | "started" | "credited" | "refunded".
- A paid snapshot's verification holds { id: "package-id", name: the identity provider's display name, type: "server", connector: its id, checks: ["identity", "aml"], package: true } on the identity and full tiers and { id: "package-acc", name: the accreditation provider's display name, type: "server", connector: its id, checks: ["accreditation"], package: true } on the full and reverify tiers; use.identity and use.aml are ["package-id"] on identity and full; use.accreditation is ["package-acc"] on full and reverify.
- Tier: reverify when invitation.existing and invitation.reverify are both true (the flag is kept by plan 08-09; until then no invitation reaches it), full when verification.accreditationRequired === true, otherwise identity.
- usePackages(...) returns an object; plan 08-15 adds its route helpers to that object (gate, start, settings, connector list) and reads packageState(rec).
