**Contract (the browser plans 08-06, 08-13, 08-07 and 08-09 build against it; do not rename):**
- The console sends invitation.package === true and invitation.clientId (its own invitation id, letters, digits, underscore, hyphen, 1 to 80).
- POST /v1/invitations then answers as today, or 402 { error, code: "no_card" | "card_declined" | "authentication_required" }, 403 { code: "account_required" }, 409 { code: "billing_unavailable" | "package_unavailable" | "already_sent" }; on each of these nothing is stored and nothing is sent.
- Rows of GET /v1/invitations carry package: null or { tier, status: "paid" | "started" | "credited" | "refunded" }.
- For a paid package the stored snapshot's verification holds two server-built connections: { id: "package-id", name: the identity provider's display name, type: "server", connector: its id, checks: ["identity", "aml"], package: true } and, on the full and reverify tiers, { id: "package-acc", name: the accreditation provider's display name, type: "server", connector: its id, checks: ["accreditation"], package: true }; use.identity and use.aml are ["package-id"] on the identity and full tiers; use.accreditation is ["package-acc"] on the full and reverify tiers.
- The reverify tier applies to an invitation with existing and reverify both true (the flag itself is kept by plan 08-09; until then no invitation reaches that tier).
