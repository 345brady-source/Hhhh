# Phase 01.4 Plan 66: Offering intake rerouted to the portal's reading server Summary

The offering intake now sends the prompt it has always built to POST /v1/intake on the portal's server, which reads it on CARROWVALE_API_KEY (the current Opus, white-labelled) and streams the reply back. The viewer's own model has no path left. Every protected intake function is byte-identical. Nothing was measured on a document and nothing was spent: every run used fakes, with no key.

## What was built

- **Install (D-31):** `npm view @anthropic-ai/sdk@1.8.0 repository.url` printed the anthropics/anthropic-sdk-typescript repository, and the approval line in D-31 was found. Then `npm install --save-exact @anthropic-ai/sdk@1.8.0` in server/ only. The lockfile is committed and `server/node_modules/` is ignored. The client pulled in 7 dependencies of its own (8 packages in all), and npm reported 0 vulnerabilities.
- **server/lib/model.mjs** exports `createClient` (async; null with no key or no library; `apiKey` from CARROWVALE_API_KEY, `authToken: null`, fixed base URL, timeout, `maxRetries: 1`, the injected fetch, client logging off), `available`, `MODEL`, `effortOf` (default high), `maxTokensOf` (default 64000, 1024..128000), `outcomeOf`, `errorReason` (works from the error's class only), `PRICES`, `DEAREST`, `usageOf`, `costOf` ({ usd, flagged }), `createBudget` and `logLine`.
- **server/lib/intake.mjs:** `createIntake({ env, fetch, timeoutMs })` returns `available`, `budget`, `maxTokens`, `count` and `run`. `run` builds exactly the request in the interfaces block: messages `[{ role: user, content: prompt }]`, adaptive thinking, the effort setting, the fallback beta with `fallbacks: 'default'`, and no system, tools or format. It streams text deltas and parses the reply: only end_turn counts; a code fence is dropped and the text from the first { to the last } must parse as a plain object. A 600 s limit covers the whole call, on top of the client's own timeout.
- **POST /v1/intake** sits after the origin, token and POST rate checks, inside its own try/catch, so the global handler never sees it.
  - It answers 503 `unavailable` before reading the body. A bad prompt gets 400 `invalid`; a body over 2 MB or a prompt over 500000 characters gets 413 `too_large`.
  - The spend cap is checked after validation and before the 200 head: 402 `spend_cap`. A failed token count also gets 402.
  - Otherwise: a 200 ndjson stream of `{t}` lines, `{h:1}` after 15 s of silence, and one last line.
  - When the browser closes the connection, the upstream call is aborted.
  - Each call writes one read-log line. A failure prints one console line with its reason and HTTP status only.
- **GET /health** now includes `reader`.
- **assets/js/intake.js:** only the two reading bodies changed.
  - `claudeSample()` now returns `{ url, token }` from the workspace's Integrations server, or null. It makes no request and keeps no cache.
  - `readWithClaude()` posts the unchanged prompt and reads the ndjson stream. `onText({ text })` gets the text received so far. Errors throw the codes ik-read already maps.
  - `NS.intake.SERVER_LIMIT_MS = 630000` sits on its own line after the export line.
  - The comments that described the viewer path were rewritten in neutral words. console.js was not edited.

## Measure part (D-34 tooling; plan 67 runs it)

`node checks/intake-server.js --only measure --doc <pdf> --out <dir> [--cap 1.00] [--max-tokens 24000] [--fake]`

- **Real mode:** needs CARROWVALE_API_KEY; without it the tool prints NOT RUN and exits 2. It spawns `node server/index.mjs` on port 8798 with a fresh API_TOKEN, STORE_FILE and CARROWVALE_READ_LOG in <dir> (the log is kept), the cap and output limit from the flags, and NODE_USE_ENV_PROXY=1. It waits up to 20 s for /health to show reader true. A fallback for network with no model call is retried once without NODE_USE_ENV_PROXY.
- **Both modes:** the tool uploads the PDF under its own file name on a fresh intake, captures the /v1/intake response through the harness route, and writes raw.json, profile.json and run.json { outcome, why, seconds, readingMs, counted, maxTokens, model, usage, cost, spent, method, firstNote, trimmed }. firstNote is kept only when it is one of the known fallback sentences, so no document text gets into run.json.
- **Fake-mode proof on the public RockStep PPM:**
  - First run: `outcome read, 1.2 s, cost $0.3263, 15 terms filled`. The cost is the fake usage priced; raw.json equals the fake reply; profile.json equals its normalized form.
  - Second run in the same folder with cap 0.01: `outcome cap`, with the built-in profile and the could-not-finish note. The cap counted the folder's earlier call ($0.3263).
  - Nothing was spent: the usage and cost are fake.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Stop was reported as "could not finish"**
- **Found during:** Task 2, part failures (case stop).
- **Issue:** the stream reader rejects with an AbortError DOMException, whose numeric `code` (20) was passed through as the error code, so ik-read showed the generic note.
- **Fix:** only an error with a string `code` is passed through; anything else is mapped (cancelled when Stop was pressed).
- **Files modified:** assets/js/intake.js (readWithClaude body only). **Commit:** a8b2cbb

**2. [Rule 1 - Plan fact corrected] The key header**
- **Found during:** Task 1, server test.
- **Issue:** the plan said the request carries `x-api-key`. Installed client 1.8.0 sends an explicit apiKey as `Authorization: Bearer <key>` (confirmed in client.js).
- **Fix:** the test asserts that this header equals CARROWVALE_API_KEY while ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN and ANTHROPIC_BASE_URL hold other values. It also asserts that no ambient value appears in any header and that the request goes to the fixed base URL. **Commit:** ddb5c68

**3. [Order] model.mjs and the intake outcome mapping were written complete in Task 1**
- Task 1 did not use the stub budget and the failed-only mapping the plan allowed. As a result, the Task 2 server tests were green on their first run, except for one test case that was written wrong (an array reply that the plan's own first-{-to-last-} rule turns into an object). That case was replaced with an unparseable span.
- The Task 2 browser parts (failures, measure) were written before the browser changes they test. Part failures went red on Stop, which led to the fix in item 1.
- TDD RED was therefore not observed for the Task 2 server cases.
