## Configuration that started

- **Build:** the bundle build, loaded as a **module worker** with `new Worker(url, { type: 'module' })` from `assets/vendor/formread/places-worker.js`.
- **How the files load:** the worker loads `runtime.min.js`, `runtime-wasm.js` and the model script with dynamic `import()`. It unpacks the text with DecompressionStream('gzip').
- **Runtime settings:** `env.wasm.wasmBinary` is set to the decoded bytes, with `numThreads = 1`, `proxy = false`, `logLevel = 'error'`, and `InferenceSession.create(bytes, { executionProviders: ['wasm'] })`.
- **Messages:** `start {modelScript}`, `run {pixels, w, h, id}` and `stop`. Replies are `ready {threads}`, `maps {data, w, h, classes, id}` (the data buffer is transferred) and `error {code: load|compile|run, detail}`. The detail is for the console only.
- **Input checks:**
  - A model script must come from the worker's own origin and end in `.js`.
  - The picture must be a Float32Array of exactly w*h values, each side from 16 to 4096.

## Deviations from Plan

1. **[Rule 3 - Blocking] Worktree recreated.** The isolated copy was removed after the checkpoint return, because it held no commits. To avoid building in the main checkout, it was recreated with `git worktree add` at the plan's base d1109205, on the same agent branch name `worktree-agent-a2653fd62765cf608`. The main checkout was not touched.
2. **[Plan-anticipated switch] Bundle build instead of the plain build.**
   - **Why:** the plain build's loader names `ort-wasm-simd-threaded.mjs` and imports it by address unless the glue is embedded. That file is not among the files the owner approved. The bundle build carries the glue inside, so `runtime.min.js` holds the package's `dist/ort.wasm.bundle.min.mjs` (73,054 B, not the 50,196 B plain file).
   - **What changed:** the worker is a module worker and uses dynamic `import()` instead of `importScripts`. This matches the plan's own fallback. The `.js` name is kept because the server's type for `.js` is the script type that a module needs.
   - **Not tried:** the plain build was not run in the frame. The reason is the code evidence above.
3. **[Rule 3 - Blocking] The licence text came from the upstream repository.** The package carries no LICENSE file (its package.json says MIT, and its README links to the repository). `LICENSE-runtime.txt` is the upstream repository's LICENSE at tag v1.30.0, copied word for word (MIT, "Copyright (c) Microsoft Corporation").
4. **[Rule 3 - Blocking] The probe network was written without a model library.**
   - **Why:** no training virtualenv exists in scratch, the research probe's model file was not kept, and installing the model library is another plan's package gate.
   - **What was done:** `runtime-frame.js` writes the same network as `make_fcn.py` itself as a model file (Conv, Relu, Resize and Add, opset 17), with made-up weights from a fixed seed. The runtime accepted it and produced 6 x 264 x 204 maps.
5. **measure.js hash.** measure.js has no entry in owner-set/hashes.json, so there was no recorded hash to re-record. Its new hash (`f4c3173f35d2`) and the reason for the change are a dated line in owner-set/reasons.txt. A copy of measure.js from before the change is at `SCRATCH/exec-0145/measure.js.before-01.4-05`.
6. **Extra check.** `ready` carries `threads`, so the "one thread" line can read it from the runtime itself.
