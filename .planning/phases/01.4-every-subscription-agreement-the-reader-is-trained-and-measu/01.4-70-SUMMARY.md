# Phase 01.4 Plan 70: Agreement reader sends the text list and the page pictures together (D-43) Summary

The subscription-agreement reader now sends the PDF, the full text list of numbered places, and a numbered picture of every page that has a place, on text agreements as well as picture agreements. Fields still land on the PDF's exact geometry.

**Nothing was spent.** Every run used fake readers with no key. SCRATCH/blind/ was never opened. **Accuracy is not measured.** The owner's numbers in D-43 (80.9 percent text only, 90.8 percent pictures) came from the earlier picture-only experiment, not from this code. Whether text plus pictures does as well still needs a measured run on the blind agreement, and then the owner's own check.

## Failures first

No gate is red. Things to know:
- **Bigger requests.** On the first agreement, the one-request body went from about 200,000 characters to about 3.1 million: 9 pictures of about 320,000 characters each.
  - A long agreement with places on about 70 pages would come to about 22 MB, still under the 31 MB range limit. Anything larger is halved, as plan 69 does.
  - Input tokens and cost per reading will rise. I did not measure by how much, because that needs the key.
- **The plan 64 exact-request path is no longer reached from the browser.** Any agreement that has places now carries pictures. The server still accepts a request without images. Its test ("without images and range the request is plan 64's exactly") stays and still passes.
- TDD order: the implementation came before the new checks, so RED was never observed.

## What changed

- **esign.js `serverReading`:** `imaged` = picture pages ∪ pages that appear in the candidate list. `bodyOf` sends one `markedPicture` per pictured page in the range. This is the same function and the same settings as plan 69: long side 2000 px, quality 0.85, every candidate outlined and labelled `#id`. A text page keeps its words in the list. A page with no place gets no picture. The pictures count toward `RANGE_BYTES` (31 MB) and `IMAGE_MAX` (600). A range over either limit, or answered 413, is halved as before. `fromAnswer`, the snapping and `candidates()` are unchanged.
- **read.mjs SYSTEM:** one new line, right after the opening paragraph: "Pictures of pages, when attached after the PDF, show the same numbered places as the list, each outlined and labelled #id: use the pictures to see the layout, shading and captions around each place, and the list's numbers to answer."
- **Comments and README:** read.mjs, index.mjs and the README now describe images for every page that has a place.
