# Phase 01.4 — Validation Strategy

> Source: `01.4-RESEARCH.md` § Validation Architecture. The planner fills the per-task map.

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Node + Playwright through the portal's real upload screen; Python scorers; all outside the repository (`SCRATCH/edgar/measure/`) |
| **Quick run command** | `run.js --docs quick.json --exact` (train documents; gold gate with rows, held-out A totals only); `run.js --only <ids>` for the train documents a task touches |
| **Full suite command** | `run.js` on the whole EDGAR set (about 18 minutes for 220), `exact.py` on held-out A (and B once frozen), the owner-document scorers and pins (`owner-set/measure.js`), the picture-form gate, proof steps, the nine check files, class pages |

A check that cannot find its documents prints NOT RUN and fails. Held-out documents are never used to tune rules, set thresholds or train models, and are blind to builders by tooling: exact.py prints held-out totals only; per-document detail only with --audit (plan 36, and a non-builder gap-closure audit after a held-out B miss).

## Sampling Rate

- After every task commit: the documents and classes the task touches, plus the owner-document scorers on the files it changed
- After every plan: the whole EDGAR set, the train exact gates (gold, train) with ratchet, held-out A totals only (builders never see a held-out document's own row; D-22), guard.py --artifacts and the read seal, the no-regression gates (picture-form gate, class pages, owner-document measure, proof steps)
- Before verification: everything green; held-out B scored once, at the end
