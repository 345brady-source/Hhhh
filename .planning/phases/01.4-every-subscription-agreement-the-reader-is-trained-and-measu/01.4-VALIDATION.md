# Phase 01.4 — Validation Strategy

> Source: `01.4-RESEARCH.md` § Validation Architecture. The planner fills the per-task map.

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Node + Playwright through the portal's real upload screen; Python scorers; all outside the repository (`SCRATCH/edgar/measure/`) |
| **Quick run command** | `exact.py` on the held-out set from saved runs; `run.js --only <ids>` for the documents a task touches |
| **Full suite command** | `run.js` on the whole EDGAR set (about 18 minutes for 220), `exact.py` on held-out A (and B once frozen), the owner-document scorers and pins (`owner-set/measure.js`), the picture-form gate, proof steps, the nine check files, class pages |

A check that cannot find its documents prints NOT RUN and fails. Held-out documents are never used to tune rules, set thresholds or train models.

## Sampling Rate

- After every task commit: the documents and classes the task touches, plus the owner-document scorers on the files it changed
- After every plan: the whole EDGAR set, exact score on held-out A, the no-regression gates
- Before verification: everything green; held-out B scored once, at the end
