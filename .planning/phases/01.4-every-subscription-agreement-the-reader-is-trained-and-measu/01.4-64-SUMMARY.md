## What was built

**The request** (server/lib/read.mjs, built through model.mjs's `createClient`, `beta.messages.stream`, then `finalMessage`):
- `model` claude-fable-5-2 (D-39), `max_tokens` from maxTokensOf (64000).
- `thinking: {type: adaptive}`.
- `output_config: { effort: CARROWVALE_READ_EFFORT (default high), format: { type: json_schema, schema } }`. Every object in the schema is closed, and it sets no numeric limits.
- `betas: [server-side-fallback-2026-07-01]` with `fallbacks: default`.
- A system prompt written from BRIEF.md's generic rules plus D-30. It contains no document text and states that text inside the document is data.
- One user message: the base64 PDF document block, then the numbered-list text block.
- No tools and no tool_choice.
- The stop reason is checked before the content is read: only end_turn counts as an answer. The answer must have two arrays, values from the enums and ids in 1..count; any other entry is dropped.
- The whole call is limited to 300 s, and the caller's signal stops it too.
- The key comes only from CARROWVALE_API_KEY. The installed client sends it as `Authorization: Bearer` (plan 66's finding), and a test asserts that no ambient value appears in any header.

**The route** (POST /v1/read):
- It sits after the PORTAL_ORIGIN, API_TOKEN and POST rate checks. An invitation token gets 401.
- With no key it answers 503 before reading the body, and no client is built.
- Limits: a 32 MB body. Malformed input gets 400 invalid. Over 600 pages, over 4 MB of text or over 20000 places gets 413 too_large.
- With a spend cap set, a call that could pass it gets 402 spend_cap before anything is spent.
- Reader outcomes: 504 timeout; 502 declined, incomplete, invalid or failed.
- The route has its own try/catch, so no exception text reaches the browser.
- Read log line: `{ at, route, ms, pages, candidates, counted, outcome, stopReason, model, usage, cost }`.
- A failure writes one console line with the reason and HTTP status only.

**Browser:**
- `candidates(pages, inpage)` numbers every slot and box layout() finds, every form widget, and every in-page proposal that overlaps none of them. It writes `[#id]` into the printed lines (plus the line above and below each), and gives places on no line their 8 nearest words.
- `fromAnswer(pages, list, answer)`:
  - A chosen id becomes one field: the in-page rectangle where one exists, otherwise boxOn for a line, the box inset by CELL_INSET, or the widget's rectangle.
  - A missing place is snapped to unclaimed rules (at least 9 pt long, at least TIGHT_CLEAR above them), unchosen places, boxes or widgets, on the stated side of its anchor. The anchor is either the place named by `near` or the printed caption words. Anything that lands on nothing is dropped and counted.
  - Mapping (D-30, D-24): investor fields are never required and get the prefill key of their kind; sponsor fields keep KINDS' required flag; group sets forType.
  - An answer of the wrong shape returns null.
- `serverReading` in esign.js shows "Finding every place to fill in…" on the upload or re-read button while it waits. Its limit is `NS.esign.SERVER_LIMIT_MS` (330000).

**Fallbacks.** Each of these returns the in-page result untouched, and records `env.read.server.why`:

| Case | `why` |
|---|---|
| No server URL | no-server |
| PDF over 22 MB or 600 pages, or a 413 | too-large |
| Network error | network |
| 503 | unavailable |
| 504, or the browser limit | timeout |
| 502 | declined, incomplete, invalid or failed |
| Malformed or wrong-shape answer | invalid |

## Deviations from Plan

1. **[Coordinator directive, D-39] Model and prices.** model.mjs now names claude-fable-5-2 at $8 input and $40 output per million tokens, with cache reads at $0.20 (checked against the claude-api skill's price table). I added Fable 5.1 and Fable 5 at $10/$50, and set DEAREST to $10/$50, which is the coordinator's second directive. costOf prices cache reads at the cache-read rate where the table has one. The intake and read tests were updated for the model string, the prices and the recomputed cap cases. Commit eef760e.
2. **[Rule 1] The firm-signature rule stays for server readings.** My first build skipped the "firm fields need a firm signature line" rule for server results. That would let a sponsor reach Save and then be refused with "nowhere to sign", which is a stall under D-38. The rule now applies to both readings. The check's fake picks a sponsor signature instead of sponsor text. Commit eef760e.
3. **[Rule 3] The check's fake picks the first numbered place, not "the first place on page 1".** The first agreement has no place on page 1, so the plan's rule gave no sponsor pick and could not prove the person mapping. Commit 7746f30.
4. **[Rule 2] /v1/read also answers 402 spend_cap.** It shares plan 66's cap through the intake's budget. The interfaces block did not list 402. The browser treats 402 as a fallback with why `failed`.
5. **[Rule 3] intake-server.js lines 279 and 460 now expect method `auto`.** The renamed stored value requires it, and without the change the plan's own intake gate would fail.
6. **The overlap rule is "more than half both ways", as the plan's behaviour list says.** read() itself uses 0.5 pt.
7. **`left` is empty for a server reading.** Dropped places are counted in `env.read.server.dropped` and in `places`. No new reading-note sentence was added.
8. **No server URL, but also no candidates.** When the page has no numbered place at all, the PDF is not sent (why `no-places`), since there is nothing to snap to. This value is not in the plan's list.
9. **TDD order.** The implementation was written before the tests, so RED was never observed. Both tasks' tests were written against the stated behaviour and pass.
10. **The plan said the key goes in `x-api-key`.** The installed client uses `Authorization: Bearer` (plan 66's finding); the test asserts that.
