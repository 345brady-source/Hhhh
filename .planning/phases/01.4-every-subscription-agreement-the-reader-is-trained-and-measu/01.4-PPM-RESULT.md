## Method

- **Keys before readings.** All three keys were written by the plan 67 executor, who built none of plans 64, 66, 68 and 69, before any reader output existed. Each was then hash-frozen in a commit message:
  - ppm.pdf: SHA-256 f11299bb86feacc8e1518ac661d991fd04d126dfd91ffb0d0b8b1d20ff7e4ea5, commit dc50810 (72 stated, 41 not stated);
  - ppm2.pdf: SHA-256 8fcb3aa988507a94e699dd479b3919d2233dbe50edfd6a18be46ce1b55015711, commit 36380a0 (52 stated, 48 not stated);
  - ppm3.pdf: SHA-256 83606696a44e4e0cc2fca695a8d0b73f8c392d05b2f644faa911712a5e6fd6c1, commit 861c6ff (47 stated, 41 not stated). It was written after the reading rules of 40fc96f, by the same executor, who built none of the reader code. One filled-rule addition was fixed in it before the reading: a stated boolean false is filled by a reader false.
  - Both hashes were checked again before scoring and matched.
- **One command per document.** The orchestrator ran cmd2.sh (text) and then cmd.sh (pictures), each once, each alone on its own server, with the key only in that process's environment. The executor never had the key. What happened was decided only from each run's own run.json, health.json (reader true for both), read log and cmd.log.
- **Probe and worst case.** Before any spend, each command made a zero-spend probe with a $0.000001 cap: the server makes only its free token count and refuses the request. The command then took the counted tokens (scaled by pdfOf / pdfPages on the PDF path) and priced the whole document at model.mjs's worst-case prices, $10 input and $50 output per million: worst = tokens × $10/M + max tokens × ranges × $50/M. If that was over the test cap, the command stopped with nothing spent. The model that served both readings was claude-fable-5-2, at $8 / $40 per million.
- **Paths taken (run.json):**
  - ppm.pdf went as a PDF (sent pdf, one request, ranges 1 to 98 of 98, pdfOf 98, trimmed false), because its text layer cannot be extracted.
  - ppm2.pdf went as text (sent text, one request, the whole text, trimmed false).
  - ppm3.pdf went as text (sent text, one request, the whole text, trimmed false), at a $3.25 test cap.
- **Max tokens:** 64000 for ppm.pdf, 32000 for ppm2.pdf and 32000 for ppm3.pdf. Each was used as set (one attempt each, no test-cap fitting).
- **Paths not scored:** reader-written prose (offering.summary, term.note, investorTerms, update, notes, sources, confidence) and derived values (offering.shortName, term.fromYears).
- **Matching rules (D-35):**
  - A term is filled when the raw reply's value is non-empty. null, '', false, [] and {} count as empty, the intake's own merge rule; 0 is a value. The value judged is the profile's normalized value.
  - Numbers must be equal as numbers. Dates, enums and booleans must be equal. Text must have the same meaning; each text term has a one-line reason recorded in score.json.
  - Array items are matched as follows: classes by name meaning, providers.others by role and name, tiers by order, fees.other by meaning.
  - Invented = a filled path the key lists as not stated, plus each filled field of a reader item that matches no key item.
  - Score = right / (stated + invented); it passes at 0.90 or more.
- **Where ppm2.pdf lost points.** 10 of its 22 lost points come from list structure:
  - the inserted tier shifts the order match (1 wrong, 2 missed, 3 invented);
  - extra provider items (4 invented, 2 of them the provider the key left out).

  The other 12 lost points:
  - the class-level management fee key flaw (3 invented);
  - four fees.other items (4 invented);
  - five terms left empty: one class (name and eligibility), the fund-level preferred return, the first tier's rate, and the distribution target.

  With both key flaws counted in the reader's favour, the score is still 74.2%.
- **Scope:** these are three documents, so three measurements, not a launch-level sample.
