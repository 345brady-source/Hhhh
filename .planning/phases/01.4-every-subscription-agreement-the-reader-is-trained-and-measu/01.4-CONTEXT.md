# Phase 01.4: Every subscription agreement — Context

**Gathered:** 2026-11-14
**Status:** Ready for research
**Source:** the owner's own words in chat (verbatim where quoted)

## Why this phase exists

The owner tested the reader on a subscription agreement it had never seen (a public EDGAR filing, printed from the EDGAR web page) and it could not read it. The owner: "it was never made to these 4, they were examples to learn from"; "it needs to be able to read a trillion different formats no two sub docs are the same"; "this is needed for launch!"; "now fix the goddamn reader, dont train it to read four files, train it to read every sub document ever, you yourself need to go to the edgar site, pull subscription agreements and train the model."

## Locked decisions

- **D-01:** The target is every subscription agreement a sponsor may upload, in any format, not a list of known layouts. The owner's four documents and the public documents so far are examples to learn from, nothing more.
- **D-02:** Claude itself goes to EDGAR (public filings, sec.gov) and pulls a large, deliberately varied set of real subscription agreements: different issuers, law firms, offering types (Regulation A, Regulation D, S-1, N-2 and interval funds, REITs, BDCs, LP and LLC funds), decades, and file forms (HTML exhibits, PDFs filed as PDF, scanned pictures, and HTML printed to PDF by a browser, portrait and landscape, as the owner did). Target: 150 to 250 documents.
- **D-03:** "Train" means: the reader's rules are developed and proved on that set, and every build is measured on all of it. Each failure is fixed only as a rule for a whole kind of layout (never for one document), and every rule is re-proved on the whole set before it ships. If a learned component (a model) would read better than rules for some part, the research says so with evidence; a learned component must run in the browser with no provider secret and no document leaving the browser, or it is not used.
- **D-04:** Measured, never judged by eye alone. Every document in the set is scored automatically on every build by checks that need no answer sheet (no field over printed words; no field off a printed line, box or cell; every printed line, box, cell and form field of a fill-in kind gets a field; every document's signature places found; nothing silently left without a field). A stratified sample (at least 40 documents) gets full answer sheets (place, kind, person) and is scored exactly. The numbers are reported per build: places found, strays, wrong kind, wrong person, unreadable documents.
- **D-05:** The owner's EDGAR file that failed (`SCRATCH/edgar/d1/doc.pdf`: a browser print of the EDGAR page in landscape; each form page a picture split across two PDF pages; white fill-in boxes on a grey background with no drawn edges) is in the set and must read.
- **D-06:** Nothing already working may break: the owner's four documents keep their scores (A 29/29, B 2/2, C 138/138 with RESULT: PASS where they pass today, the picture form 241/241 with 0 kind, owner and name differences), the first agreement's 47 fields with none marked, the public documents' pins, the nine check files and the class pages.
- **D-07:** The safe default stays: the reader never invents a field where nothing is printed and never silently skips a printed place; when unsure it places the field and marks it for the sponsor.
- **D-08:** Documents stay out of the repository. EDGAR filings are public, but the set and its answer sheets live in the scratch folder; committed files refer to documents by an id only. No product or vendor names in the UI. No new dependency beyond the one approved text-recognition library unless the research proves one is needed and the owner approves it.
- **D-09:** No time promises. Report what is finished and what it measured. Show the owner real results on documents the reader had never seen; nothing is called ready before the owner has checked it.
- **D-10:** Requests to EDGAR identify the client generically (no personal name or email) and respect SEC's fair-access limit (at most 10 requests a second; stay well under).

## Owner's decision on scope and means (2026-11-14, verbatim)

"make sure during planning the end result has to be a finished product capable of reading and correctly placing fields on any sub doc, this is the final run, you can do anything in your power to accomplish this, pull files download skills/pluggin i dont care just train the system right this time and have it work as it should"

- **D-11:** The phase's end result is a finished product: the reader reads and correctly places fields on any subscription agreement. This is the final run on this feature; the plan must reach that, not a partial step.
- **D-12 (supersedes the dependency limits in D-03 and D-08):** Any means is allowed: new libraries, trained or pretrained models (for example a form-field detection model run in the browser, or a document-layout model), a server-side reading service, skills or plugins, more public documents. The owner has approved new dependencies for this. The research must compare the realistic options on evidence (accuracy on the EDGAR set, speed, size, licence, privacy) and recommend the one that gets closest to "any sub doc, correctly"; the planner builds that. Privacy still holds unless the owner decides otherwise: documents hold investors' personal details, so an option that sends a document off the sponsor's computer must say so plainly and is put to the owner before it is built.

## Owner's decision: the portal does all of it (2026-11-14, verbatim)

"nothing can run in the sponsors browser, it has to run in the portal, all they are doing is uploading theyre docs, all your doing is reading them and placing the fields correctly, understand? no more work for the sponsor, it all falls on the portal"

- **D-13:** The sponsor's only action is uploading the agreement. Reading and placing every field is the portal's job, done automatically. No "Read these pages from their picture" button, no page-by-page confirmation, no fields left for the sponsor to move or fix. The reading runs in the portal itself (on the portal's own servers is allowed and expected), not as work in front of the sponsor.
- **D-14 (refines D-07):** Review marks are a last resort, not a workflow. The measure counts every field the sponsor would have to check, move, add or remove as a failure. The target is an agreement that is ready to send as soon as it is uploaded.
- **D-15 (refines D-12's privacy note):** The sponsor uploads the agreement to the portal, so reading it on the portal's own servers is within what the sponsor already does. Documents must still never go to a third party unless the owner approves that third party by name, and are stored and handled with the care investors' personal details need.

## Owner's decision on the model provider (2026-11-14, verbatim)

"the provider cannot be named if using an api, it has to white labeled to me"

- **D-16:** A hosted model API may be used for the labelling step, behind the portal's own reading service. It must be fully white-labelled to the owner: the provider is never named or visible anywhere a sponsor or investor can see it (screens, messages, emails, documents, file names, network calls from the browser, error text). All calls to it go from the portal's server, never from the browser. The provider's terms must give zero data retention and no training on inputs.
- **D-17 (defaults in force until the owner says otherwise):** hosting company chosen by the owner before launch (the service runs on any standard Linux server); public EDGAR filings may be sent to the model for measurement (no client agreement or the owner's own documents without the owner's approval); the reading service deletes an uploaded PDF as soon as its fields are placed and keeps the result at most one hour.

## Owner's clarification (2026-11-14, verbatim): the web page is fine

"when you said browser earlier i thought you meant the sponsor needed to download pluggins or something for it to work. the sponsor will only upload a document and the reader will place the fields, nothing more from the sponsor, if that happens in a webpage it is fine"

- **D-18 (supersedes the "on the portal's own servers" part of D-13, and D-15 to D-17 where they assume a server):** The reading may run inside the portal's own web page, automatically, as it does today. What is forbidden is any extra step for the sponsor: no install, no plugin, no button to press, no confirmation, nothing to fix. A server is not required. Preferred design: everything runs in the page (no hosting cost, no third party, white-label by nature); a server or hosted model is used only if the measure proves the page cannot reach the target.
- **D-19:** The owner asked "is this not something that we can build" and preferred no outside company. Preferred approach: our own small models trained on the EDGAR set (a field-spotting model for places geometry misses; a classifier for kind, person and label from the words around each place), run in the page, guarded by the existing rules. A large open model or a hosted API only if the measure proves the small models cannot reach the target, and then put to the owner first.

## Owner's decision: the end goal and not stopping (2026-11-14, verbatim)

"exactly, now the sponsor still needs the abillity to add or correct anything but they shouldnt have to. now, do not stop until this is complete and the final product is ready to be delievered, do not except failure or anything have ass, if 220 filings isint enough run 1000, do not stop working until this is complete"

- **D-20:** The end goal (agreed with the owner): a sponsor uploads any subscription agreement and it is ready to send with nothing else to do; every place found, every field on its printed place and none elsewhere, the right kind, person and label, any format, inside the portal's own page, white-label. The editor stays: the sponsor can still add, move or correct any field, but should never have to.
- **D-21:** Do not stop until the final product is ready to deliver. No half measures, no accepted failure. If 220 filings are not enough to reach the goal, collect more (up to 1000 or beyond) and keep training and measuring.

## Owner's decision: the cheaper path (2026-11-14)

The plan checker estimated the first plan at about 16-27M tokens (473 hand-written answer sheets before any reader fix) against 4.5M stated, and proposed a cheaper path of about 10-11M tokens to the same goal. Offered "1. the cheaper path (recommended)" or "2. the plan as written", the owner answered: "1".

- **D-22:** Reader fixes ship first, biggest yield first, so every wave leaves a better reader if work stops. About 113 full hand-written answer sheets (about 50 train, including picture, scan and broker forms, plus the 63 of held-out B), at most about 6 documents per executor; the other training labels are bootstrapped where the improved reader and the upgraded measure agree, with an agent adjudicating only disagreements; the 231 added documents are not fully sheeted. Held-out A and B are blind to builders by tooling (totals only; per-document detail only for the audit plan). Same goal (D-20) and same targets.

## Owner's decision: the owner's documents may go to GitHub (2026-11-15, verbatim)

"No you can move them to get hub, when did I make that a rule?"

- **D-23 (supersedes D-36 of 01.1, D-24 of 01.2, the confidentiality line of 01.3's context, and D-08 here where they keep the owner's documents and their answer sheets off GitHub):** The owner never made that rule; it was the orchestrator's own precaution. The owner's documents, their answer sheets and scorers, and the EDGAR working data are saved on the separate `reader-data` branch (never merged into the product branch). The product branch's code and committed planning files still name no document text (white label and tidiness, not confidentiality).

## Owner's decision: labels do not matter (2026-11-15, verbatim)

"Labels shouldn't matter, the only thing it should do is recognize what fields need to be inputed and where, it doesent need to know the reason behind it"

- **D-24 (refines D-20, D-01 and the targets):** A field's label is no longer judged. "Exact-ready" and "right first time" mean: every place found, exactly on its printed place, no strays, the right kind, and the right person (who completes it decides which signer gets the field, so it stays judged). Label differences are reported for information only and block nothing. The meaning model does not need to predict labels; a field keeps a plain label from its kind (or the caption words the reader already has) so the signer sees something sensible.

## Owner's decision: one last check on 100 fresh agreements (2026-11-15, verbatim)

"When you believe it is finished do one last final check, where you pull another 100 random subscription agreements and test it on them, only search and pull them after everything has been completed, then give me the results"

- **D-25:** After every other plan is complete and the reader is frozen, and only then, 100 new subscription agreements are searched for and pulled at random from EDGAR (none in set A, set B, set C, held-out A or B; a random draw across years and offering kinds, not chosen by anyone who built the reader). The frozen reader is run on all 100 through the real upload screen and scored: the whole-set measure on all 100, and full answer sheets written for a random 20 of them by agents who build nothing, scored exactly. No reader change between the draw and the result. The results go to the owner as they come out, failures first, before the owner's check.

- **D-26 (owner, 2026-11-15, verbatim: "Run another random 50 as pictures as well"):** In the same final check, a further 50 new random subscription agreements (none in any set, held-out list or the 100 of D-25) are drawn after the reader is frozen and turned into pictures before the reader sees them: every page rendered to an image and made into a picture-only PDF (no text layer), half as clean renders and half with scan effects (slight tilt, noise, lower resolution, greyscale). The frozen reader is run on all 50 through the real upload screen, scored with the measure, and a random 10 get full answer sheets by agents who build nothing, scored exactly. Reported to the owner with the D-25 results.

- **D-27 (owner, 2026-11-15, verbatim: "do not stop until it's reached if you run out of usage it will reset Thursday at 12 am, do not stop until you are confident that every document uploaded will be read and placed with atleast 90% accuracy, there will be a million rounds of needed"):** The stop condition for the reader work is no longer the end of this phase. Work continues round after round (this phase, then further GSD phases) until the bar below is met on a fresh draw. A usage outage pauses the work and it resumes when usage resets; it is never a reason to stop.
  - **The bar (per document, on every document), as the owner set it on 2026-11-15 when asked to choose between 90 percent across all documents, 90 percent on each document and 100 percent on each document; answer: "Each doc 100%":** for each uploaded agreement, every answer-sheet place gets a field on its printed place with the right kind and the right person, and no field is placed where no place is (0 strays, 0 missed). Labels are not judged (D-24). A place the sheet marks with a doubt is met by any reading the sheet accepts. Measured exactly against answer sheets made by agents who build nothing. (Earlier the same day the owner had said "at least 90% accuracy"; his answer to the direct question replaces it.)
  - **Confidence:** the bar must hold on every document of a fresh random draw made after the reader is frozen for that round: at least 100 typed or filed agreements plus at least 50 picture-only (half clean, half scan effects), never seen in any earlier set, held-out list or earlier fresh draw, all with full answer sheets. Every one passing on 150 fresh documents means, by the rule of three, that fewer than about 2 percent of agreements in the wild would miss the bar (95 percent confidence). One document with any miss, stray, wrong kind or wrong person means another round.
  - **On a failure (owner, 2026-11-15: "it doesent mean another round, it just means fix and try again"):** fix what failed and run the test again; repeat until every document passes. No new phase or new full draw for each failure. Because fixing on those documents means they are no longer unseen, once all pass, one last fresh draw of the same size confirms it before it is reported as met. Held-out A and B stay held out throughout.

- **D-28 (owner, 2026-11-15, verbatim: "Ok drop the bar to 90% but aim for 100% drop pictures, keep what you've done but don't improve beyond this point, when they are uploaded include a message that acknowledges it's a picture and is common with print to pdf, for increased accuracy upload a txt pdf"):** Replaces parts of D-26 and D-27.
  - **Bar:** every document of the fresh draw at least 90 percent right (place, kind, person; strays count against it), aiming for 100. On a failure: fix and test again (D-27). The fresh draw is the 100 typed or filed agreements of D-25 only.
  - **Pictures dropped:** picture-only and scanned documents are out of the bar and out of further work. What is built stays (automatic picture reading, the tracer place model, the picture-form gate, the PS sheets). No plan improves picture reading from here: no scan-effect training variants, no more scan collection (set-d stopped at what it has), no picture place-model training, and D-26's 50 picture documents are dropped from the final check. Text formats stay in scope, including landscape and tinted text prints.
  - **Message on picture upload:** when any page of an uploaded document is read from its picture, the upload screen shows a plain notice, white-label, no vendor names: the document was read from page pictures, which is common with print to PDF, and for better accuracy the sponsor can upload a PDF with selectable text. Fields are still placed as today.
  - **proof5:** re-pinned at the current picture-reading state (binder 288 as measured by plan 59, 43-page agreement 159), because picture reading is frozen by the owner.

- **D-29 (owner, 2026-11-15, verbatim: "We're starting to sacrifice quality, they do need to have no fixes at all the 90% bar is for anything that gets uploaded, for 50 documents that were training on let's try our best to get them to 100% but don't run out of usage before you can give a report"):**
  - The done-targets stay strict: held-out A 39 of 39 ready to send with no fixes (plan 50's target is kept, not relaxed). The 90 percent per-document bar of D-28 is the floor for any fresh upload, not a replacement for the no-fix targets.
  - The documents with hand answer sheets (the train documents with full sheets, about 51) are pushed toward 100 percent: every fast-path report gives how many of them are ready with no fixes and the per-document misses (train documents, so per-document rows are allowed).
  - A measured report reaches the owner before usage runs out: report after each fast-path plan lands, and never start a long run that could exhaust usage before the last measured numbers are reported.

- **D-30 (owner, 2026-11-15, verbatim: "you may be putting to much emphasis on who signs what, there should really only be two categories investor and sponsor, regardless of what the sub doc calls them, anything that is not meant to be filled or signed by the sponsor is the investor, just dont make any fields on the investor side mandatory to complete, and auto fill anything you can with information provided"):**
  - **Two people only:** every field belongs to the sponsor (the firm: acceptance, countersignature, office use by the issuer) or the investor (everything else, whatever the document calls it: subscriber, co-subscriber, joint holder, spouse, authorised signatory, custodian, broker-dealer, third party). The reader assigns only these two; the measure judges person on these two (sheet owners map: firm to sponsor, everything else to investor). The Co-investor option stays in the editor for a sponsor who wants it, but the reader no longer assigns it.
  - **Investor fields are never mandatory:** no investor-side field is required to complete signing (the investor can leave any of them empty). Sponsor fields keep their current behaviour.
  - **Auto-fill:** every investor field the portal can fill from information it already holds (name, entity name, address, email, phone, commitment amount, date, tax id where held) is filled automatically; the investor can still change it.

- **D-31 (owner, 2026-11-15, AskUserQuestion answer "API for every upload"):** Every uploaded agreement is read by a large model through the API behind the scenes, white-labelled (no provider name anywhere a sponsor or investor can see). The model decides which places are fields, their kind and whether each is the investor's or the sponsor's (D-30); the portal snaps each field to the exact printed line or box from the PDF's own geometry. The in-page reader stays as the fallback when the API is unreachable. The call runs from the portal's server piece (server/), never from the browser; the API key lives only on the server. The owner accepts that each agreement leaves the portal to be read (this replaces the earlier no-outside-company rule for the reading step only) and the per-agreement cost (about /bin/bash.20 to /bin/bash.60 estimated; one agreement per offering). Before any sponsor sees it, accuracy and cost are measured on the hand-marked agreements and the held-out sets, failures first. Model: the current Opus unless the owner chooses otherwise. Package: the owner approved installing the official @anthropic-ai/sdk in server/ only, pinned to an exact version (AskUserQuestion, 2026-11-15). The key: Anthropic hosts cannot take a network secret in this environment, so the owner adds CARROWVALE_API_KEY as an environment variable in the environment settings; it applies from the next session start.
