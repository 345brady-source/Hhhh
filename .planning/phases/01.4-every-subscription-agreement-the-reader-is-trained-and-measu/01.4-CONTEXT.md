# Phase 01.4: Every subscription agreement — Context

**Gathered:** 2026-11-14
**Status:** Ready for research
**Source:** the owner's own words in chat (verbatim where quoted)

## Why this phase exists

The owner tested the reader on a subscription agreement it had never seen (a public EDGAR filing, printed from the EDGAR web page) and it could not read it. The owner: "it was never made to these 4, they were examples to learn from"; "it needs to be able to read a trillion different formats no two sub docs are the same"; "this is needed for launch!"; "now fix the goddamn reader, dont train it to read four files, train it to read every sub document ever, you yourself need to go to the edgar site, pull subscription agreements and train the model."

## Locked decisions

- **D-01:** The target is every subscription agreement a sponsor may upload, in any format, not a list of known layouts. The owner's four documents and the public documents so far are examples to learn from, nothing more.
- **D-02:** Claude itself goes to EDGAR (public filings, sec.gov) and pulls a large, deliberately varied set of real subscription agreements: different issuers, law firms, offering types (Regulation A, Regulation D, S-1, N-2 and interval funds, REITs, BDCs, LP and LLC funds), decades, and file forms (HTML exhibits, PDFs filed as PDF, scanned pictures, and HTML printed to PDF by a browser, portrait and landscape, as the owner did). Target: 150 to 250 documents.
- **D-03:** "Train" means: the reader's rules are developed and proved on that set, and every build is measured on all of it. Each failure is fixed only as a rule for a whole kind of layout (never for one document), and every rule is re-proved on the whole set before it ships. If a learned component (a model) would read better than rules for some part, the research says so with evidence; a learned component must run in the browser with no provider secret and no document leaving the browser, or it is not used.
- **D-04:** Measured, never judged by eye alone. Every document in the set is scored automatically on every build by checks that need no answer sheet (no field over printed words; no field off a printed line, box or cell; every printed line, box, cell and form field of a fill-in kind gets a field; every document's signature places found; nothing silently left without a field). A stratified sample (at least 40 documents) gets full answer sheets (place, kind, person) and is scored exactly. The numbers are reported per build: places found, strays, wrong kind, wrong person, unreadable documents.
- **D-05:** The owner's EDGAR file that failed (`SCRATCH/edgar/d1/doc.pdf`: a browser print of the EDGAR page in landscape; each form page a picture split across two PDF pages; white fill-in boxes on a grey background with no drawn edges) is in the set and must read.
- **D-06:** Nothing already working may break: the owner's four documents keep their scores (A 29/29, B 2/2, C 138/138 with RESULT: PASS where they pass today, the picture form 241/241 with 0 kind, owner and name differences), the first agreement's 47 fields with none marked, the public documents' pins, the nine check files and the class pages.
- **D-07:** The safe default stays: the reader never invents a field where nothing is printed and never silently skips a printed place; when unsure it places the field and marks it for the sponsor.
- **D-08:** Documents stay out of the repository. EDGAR filings are public, but the set and its answer sheets live in the scratch folder; committed files refer to documents by an id only. No product or vendor names in the UI. No new dependency beyond the one approved text-recognition library unless the research proves one is needed and the owner approves it.
- **D-09:** No time promises. Report what is finished and what it measured. Show the owner real results on documents the reader had never seen; nothing is called ready before the owner has checked it.
- **D-10:** Requests to EDGAR identify the client generically (no personal name or email) and respect SEC's fair-access limit (at most 10 requests a second; stay well under).

## Owner's decision on scope and means (2026-11-14, verbatim)

"make sure during planning the end result has to be a finished product capable of reading and correctly placing fields on any sub doc, this is the final run, you can do anything in your power to accomplish this, pull files download skills/pluggin i dont care just train the system right this time and have it work as it should"

- **D-11:** The phase's end result is a finished product: the reader reads and correctly places fields on any subscription agreement. This is the final run on this feature; the plan must reach that, not a partial step.
- **D-12 (supersedes the dependency limits in D-03 and D-08):** Any means is allowed: new libraries, trained or pretrained models (for example a form-field detection model run in the browser, or a document-layout model), a server-side reading service, skills or plugins, more public documents. The owner has approved new dependencies for this. The research must compare the realistic options on evidence (accuracy on the EDGAR set, speed, size, licence, privacy) and recommend the one that gets closest to "any sub doc, correctly"; the planner builds that. Privacy still holds unless the owner decides otherwise: documents hold investors' personal details, so an option that sends a document off the sponsor's computer must say so plainly and is put to the owner before it is built.
