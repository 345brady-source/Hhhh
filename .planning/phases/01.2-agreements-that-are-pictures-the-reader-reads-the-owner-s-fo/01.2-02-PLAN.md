<objective>
Start the text-recognition engine without any network request, from the portal's own files, so that it runs under the
hosted preview's rules; and say plainly, on a page the owner can open, whether it starts on the real host.

Purpose: the prototype's reader cannot start in the preview. Measured in the reproduced frame: the preview's policy
refuses every request the page makes for data, so both language files are refused in 3 ms. A start that makes no
request (the engine's worker started from one of the portal's own files, the language data arriving as a script that
worker imports) loaded in 373 ms and read correctly there. Whether the real host lets such a worker compile WebAssembly
cannot be reproduced here (research assumption A1), so this plan also ships a probe page, and the design holds either
way: boxes are found without the engine (plan 01), and when the engine cannot start the fields are named by shape and
marked (plans 03 and 04).

Output: `assets/js/textengine.js`, two files in `assets/vendor/textread/`, `reader-probe.html`, and the kept check
`checks/reader-frame.js`. Nothing links the new module from the portal's pages yet and the two fetched language files
stay in place: plan 03 switches `assets/js/textread.js` to this start and removes them in the same change, so picture
reading is never broken between waves.
</objective>
