## Resolution

root_cause: In the product, invitations.js coMerge (since 06-39, 3349687). It took coS = the co-investor's signer from env.signers before calling esign.js importSignature, and after the import set si.signedAt = coS.signedAt. importSignature's applySignature signs a deep copy of the envelope and ends with Object.assign(env, next), which keeps the envelope object but gives it a new signers array; coS was left detached and never marked signed, so si.signedAt stayed empty on every co-investor import. Two consequences in the same Check now: coSweep, which cancels a server sign-in whose agreement no longer waits for the co-investor unless si.signedAt is set, POSTed /v1/invitations/<id>/cancel for the finished sign-in, set cancelledAt, got 409 (completed) and logged "Co-investor sign-in cancelled: <account>: the link sent to <co-investor> had already ended on the server (the agreement no longer waits for the co-investor)"; and coinvestor.js signInText, which says "Signed <date>" only when si.signedAt is set, kept "Sign-in in the server outbox <date>" (or "Sign-in emailed <date>"). The removed hook (`!si.signedAt` -> cancel) would also have sent a cancel when a co-investor who had signed was removed. Second finding (preview, no server; a design gap from 06-37, not this stale read): the local sign-in's row had no signed state, so after the co-investor signed it kept "Sign-in sent <date>".
fix: (1) invitations.js coMerge, +3 -1 (ebe8b55): after importSignature the co-investor's signer is read again from env.signers and si.signedAt is its signedAt (now, if it were ever missing after a successful import). emailFor and every other line untouched. (2) coinvestor.js, +10 (4b77e2e): coSignedAt(inv) = the latest signedAt of the account's co-investor signer on a sent or completed agreement, only when esign.js coTask says nothing waits for them and they signed; signInText's local branch says "Signed <date>" then (the server branch is untouched).
